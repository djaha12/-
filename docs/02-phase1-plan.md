# ATELIER — план Фазы 1 (MVP, пилот Бишкек)

Статус: ожидает «поехали» от Dars. Шаги 1–15 из ТЗ сгруппированы в 7 милстоунов; ни один пункт не выброшен —
маппинг в конце.

## Процесс каждого блока (инвариант)
1. Мини-план блока → 2. Реализация → 3. Ревью: design-reviewer + code-reviewer (+ qa-agent, где есть бизнес-логика)
→ 4. Доказательства: вывод тестов, скриншоты 1440/390 × light/dark → 5. Коммит → 6. Показ Dars.
Один блок = одна сессия. CLAUDE.md обновляется после каждого блока.
Для каждого экрана: минимум 2–3 цикла «скриншот → design-reviewer → правки».

## M1 — Фундамент (шаги ТЗ: 1, 2, 3)

**1.1 UX-флоу по ролям (без кода).** JTBD-карты: «клиент нашёл специалиста за 3 минуты» (гость → лента →
фильтры → профиль → заявка → регистрация в момент ценности), «специалист опубликовал кейс с телефона за 5 минут»,
«клиент сравнил троих и отправил бриф», «заказ от брифа до отзыва», «онбординг специалиста за 10 минут»,
«привязка Telegram». Текст + mermaid-схемы. → Показ.

**1.2 ERD + контракт API (без кода).** Полная схема: User, SpecialistProfile, ClientProfile, Organization,
OrgMembership, Case, CaseImage (варианты, blurhash, порядок, до/после-пары), CaseCollaborator, Collection,
CollectionItem, Follow, Reaction, Brief, BriefResponse, ChatThread, Message, Order (state machine: обсуждение →
договорённость → в работе → сдан → завершён; + отменён, спор; взаимные подтверждения), OrderCheckpoint,
Review (4 подшкалы), Verification, Report, ModerationItem, Notification, Entitlement (Free/PRO),
BoostCampaign, City/District, Style/Category, ExchangeRate, событийная схема аналитики.
Ревью backend-agent. → Показ ERD + описания эндпоинтов.

**1.3 Бутстрап.** Монорепо (pnpm + Turborepo): apps/web (Next.js 15 + TS strict + Tailwind + shadcn + TanStack
Query + tRPC), apps/services (Fastify: WS, BullMQ, grammY), packages/db|core|i18n|config. CI: lint + typecheck +
test; husky pre-commit. Субагенты .claude/agents/: design-reviewer, backend-agent, code-reviewer, qa-agent.
Skill .claude/skills/atelier-conventions. Скриншот-харнесс `pnpm shots` (Playwright: 1440/390 × light/dark).
Docker Compose dev (Postgres, Redis, Meilisearch, MinIO). Доказательство: зелёный CI, работающий харнесс.

**1.4 Дизайн-система.** Токены: тёплый белый/глубокий графит, 2–3 кандидата акцента (покажу скриншотами,
выберем один), типографика Manrope + serif-пара с кириллицей (Lora / Source Serif 4 — покажу образцы),
шкала, spacing 4px, radius, elevation, motion (150–250ms). Библиотека компонентов со всеми состояниями
(default/hover/focus/active/disabled/loading/error) + витрина /dev/ui. Dark mode с первого коммита.

**1.5–1.7 Три эталонных экрана** на реалистичных мок-данных: лента (masonry, skeleton, LQIP), профиль
специалиста, страница кейса (полноэкранная галерея, до/после слайдер, метки на фото). Каждый — итерации
по скриншотам до планки Behance/Houzz. → Показ каждого экрана отдельно.

## M2 — Идентичность и контент (шаги 4, 5)

**2.1 Auth и роли.** Телефон + OTP (Telegram Gateway + SMS-fallback за абстракцией), Google OAuth (Apple —
при выходе в App Store), сессии, роли: специалист / клиент / агентство / админ. Гость видит ленту без
регистрации; регистрация в момент ценности. qa-agent: права ролей.

**2.2 Профили.** Специалист: обложка, специализация, стили, город/район, вилка цен (сомы + USD по курсу НБКР),
статус «принимаю заказы», «работает в X». Клиент: минимальный. Статистика владельцу (просмотры, сохранения,
конверсия). Телефон скрыт до заявки.

**2.3 Кейсы.** Мастер создания mobile-first: мультизагрузка, черновики, автосейв, до/после-пары, площадь,
вилка бюджета, сроки, роль, теги коллег (совместные кейсы), чекбокс прав на фото. Пайплайн изображений:
sharp → EXIF-strip → AVIF/WebP 400/800/1600 + blurhash → R2. Лимит Free: 5 кейсов (packages/core + тесты).

**2.4 i18n + SEO-база.** next-intl: ru (источник) / ky / en; SSR-метаданные, канонические URL, латинские слаги,
hreflang. OG-карточки — базовые (полные — M7).

## M3 — Дискавери (шаг 6)

**3.1 Лента.** Masonry, бесконечный скролл, фильтры (тип/стиль/бюджет/город), ранжирование recency+engagement,
skeleton, офлайн-состояние, пустые состояния, LCP < 2.5s на 3G.
**3.2 Коллекции.** Мудборды, анимация сохранения («момент радости»), регистрация в момент сохранения для гостя.
**3.3 Поиск.** Meilisearch: специалисты и кейсы, фасеты, синонимы ру/кыр, индексация через очередь.

## M4 — Маркетплейс-луп (шаги 7, 8) — сердце продукта

**4.1 Брифы.** Публикация (задача, объект, площадь, бюджет, сроки, референсы из коллекций), лента брифов
для специалистов, отклики (лимит Free), сравнение профилей рядом (desktop — колонки, mobile — свайп-карточки).
**4.2 Чат.** WS (apps/services): текст, фото, файлы/PDF, статусы доставки, привязка к брифу/заявке/заказу.
**4.3 Заказы.** Прямая заявка в 2 клика; state machine со взаимными подтверждениями, чек-поинты с фото,
отмена и спор (арбитраж админа), авто-подтверждение «сдан» через N дней.
**4.4 Отзывы.** Только по завершённому заказу; 4 подшкалы + текст + фото; агрегация рейтинга, публичная история,
процент повторных клиентов. qa-agent: полный набор edge-cases (отзыв без заказа невозможен, повторный отзыв,
спорный заказ и т.д.). Антифрод: velocity-лимиты, аномалии → модерация.

## M5 — Рост и доверие (шаги 9, 10)

**5.1 Соц-слой.** Подписки, лайки/сохранения, публикации-посты, «Проект недели» по метрикам, челленджи —
минимальная версия (первый кандидат на перенос при сжатых сроках).
**5.2 Верификация.** Заявка на бейдж (личность, юрлицо/патент), проверка админом.
**5.3 Админка и модерация.** Очередь премодерации (trust-tiers), pHash-дубликаты, жалобы, арбитраж споров,
управление пользователями/контентом, rate limiting против парсинга.
**5.4 Seed.** 40 специалистов всех типов, 120 кейсов (Бишкек: центр, Джал, Асанбай, Кок-Жар, Магистраль,
Тунгуч + Ош, Иссык-Куль), 15 брифов, отзывы через сгенерированные завершённые заказы, цены в сомах.

## M6 — Каналы и монетизация (шаги 11, 12, 13)

**6.1 Монетизация.** Entitlements Free/PRO (лимиты, аналитика, приоритет), ручная активация + промокоды,
абстракция PaymentProvider (Mbank, O!Деньги, Элсом, Balance.kg; расширяемо на Kaspi) — интеграция по мере
получения мерчант-доступов. Буст с нативной пометкой. qa-agent: лимиты тарифов.
**6.2 Онбординг.** Мастер профиля за 10 минут, импорт-помощник из Instagram (ссылки → структура), прогресс
заполненности профиля.
**6.3 Telegram-бот + push.** Привязка аккаунта (deep-link), матрица уведомлений (заявки, сообщения, статусы
заказа, модерация), центр уведомлений in-app, web-push для PWA, настройки каналов. PWA-манифест, offline-shell.

## M7 — SEO, аналитика, запуск (шаги 14, 15)

**7.1 SEO.** schema.org (Person/LocalBusiness/Review), sitemap, полные OG-карточки кейсов/профилей,
генератор визитки кейса для сторис (вертикальный формат).
**7.2 Аналитика.** PostHog (события по схеме из M1.2, воронки, retention, feature flags) + дашборд владельца
(DAU/WAU, воронка клиент→заявка→заказ→отзыв).
**7.3 Эксплуатация и запуск.** Sentry, бэкапы БД (cron → R2), staging, оферта/политика, перф-аудит
(Lighthouse, 3G-профиль, LCP < 2.5s, CLS ≈ 0), a11y-пасс (WCAG AA), security-ревью полного среза
(инъекции, авторизация, IDOR, rate limits), README с архитектурными решениями.

## Вне Фазы 1 (заложено в архитектуре, не строится)
AI-подбор и AI-теги (событийная схема и таксономия стилей готовы под них), мини-CRM, «объект + команда под
ключ», полная мультивалютность (сом + отображение USD есть; тенге/сум — добавление записи, не переделка),
видео-кейсы и туры, кастомные домены PRO, React Native, Kaspi Pay, внешний реверс-поиск изображений.

## Definition of Done запуска
Все блоки M1–M7 показаны и приняты; e2e-смоук ключевых сценариев зелёный; тесты packages/core зелёные;
Lighthouse mobile ≥ 90 perf на ленте/профиле/кейсе; a11y-чеклист пройден; seed на staging; бэкап
восстановлен тестово; security-ревью без критичных находок.
