# ATELIER — принятые решения (Фаза 0 → 1)

Dars делегировал решения по docs/01-questions.md: «делай как считаешь эффективнее». Фиксация дефолтов:

1. **Хостинг**: Hetzner VPS + Docker Compose (web, services, Postgres, Redis, Meilisearch) + Cloudflare CDN + R2.
   Dev-окружение — docker-compose.dev.yml. Staging — второй стенд.
2. **OTP**: Telegram Gateway первичный + SMS-fallback за абстракцией `OtpChannel` (провайдер SMS подключим
   при договоре; в dev — mock-канал с кодом в логах).
3. **Instagram-импорт**: фазируем. MVP — ручная мобильная загрузка + «ссылки как помощник»; Graph API — фаза 1.5.
4. **Модерация**: trust-tiers. Новый аккаунт — премодерация первых 3 кейсов + автопроверки (pHash-дубликаты);
   далее — мгновенная публикация, пост-модерация.
5. **Холодный старт отзывов**: вариант А — строго только верифицированные отзывы по заказам. Никакого импорта
   внешних отзывов. Честность = позиционирование.
6. **Агентства**: Organization/OrgMembership в схеме БД с первого дня; UI MVP — метка «работает в X» + заглушка.
7. **Контакты**: автоскрытие телефонов/ссылок в публичном контенте (кейсы, посты, брифы); в чате — свободно.
8. **PRO**: entitlements с первого дня, активация вручную/промокодами; PaymentProvider — абстракция,
   интеграции Mbank/O!Деньги — после мерчант-договоров.
9. **Сроки**: жёсткой даты нет → полный охват M1–M7; при необходимости первыми режем челленджи и посты (M5.1).
10. **Языки**: ru — источник; ky/en — перевод с маркером `// TODO(native-review)` в i18n-файлах.
11. **Домен**: рабочее имя ATELIER; все URL/имя бота — через env (`NEXT_PUBLIC_APP_URL`, `APP_NAME`).

## §12. Фиксация после проектирования M1 (кросс-ревью 81 находка, редакторы)
- Авто-подтверждение «сдан → завершён»: **N = 7 дней**, напоминания клиенту за 48 и 24 часа.
  Авто-подтверждённый заказ помечается `autoConfirmed`, вес отзыва ниже (−0.15).
- Лимиты Free: **5 опубликованных кейсов** (считаются PUBLISHED + PENDING_REVIEW),
  **10 откликов на брифы в месяц**, **≤ 20 фото в кейсе**.
- PRO → Free (grandfathering): опубликованное сверх лимита НЕ скрывается, новые публикации блокируются.
- Отзывы: только клиент заказа, один на заказ, окно редактирования **72 часа**, окно подачи 90 дней;
  публичный ответ специалиста разрешён. Двусторонних отзывов в MVP нет.
  Пометка via_arbitration хранится, публично не показывается.
- Арбитраж спора: SLA «48 ч на позиции сторон + до 3 дней разбора»; исходы: завершить / отменить
  (отзыва нет — предохранитель от мести) / вернуть в работу; возвратов DELIVERED→IN_PROGRESS ≤ 3.
- Канонический маршрут кейса: **/case/{slug}** (как сверстан эталон).
- Гостевая коллекция в localStorage до регистрации с миграцией при auth — принято.
- Жалобы доступны гостям (reporterId nullable + rate limit по anonId/IP).
- Метки на фото (CaseImageAnnotation) остаются в MVP: модель/API сейчас, UI — в M3.
- device_cluster-антифрод (UserDevice) — модель в схеме, сбор и правила — Фаза 1.5.
- Telegram-дайджест: только батчируемые уведомления, сообщения чата и заявки — мгновенно;
  «тихие часы» настройкой пользователя, чат по умолчанию доставляется всегда.
- Win-back-рассылки в MVP исключены.
- briefs.listOpen — только специалистам (защита лидов от скрейпинга); публичная витрина брифов — решение Фазы 1.5.

## §13. Realtor-first (решение Dars, 2026-07)
- **Риелторы — первая вертикаль**, остальные специальности — вторая волна. Механики едины,
  меняются порядок доводки, дефолты, поля и копирайт (полный документ: docs/05-realtors-first.md).
- Позиционирование: «Не объявления. Репутация.» Анти-скоуп: не листинг-портал — без объявлений,
  статуса «в продаже», карт объектов, подписок на цену и ипотечных механик. Кейс = история сделки.
- Бейдж «Подтверждено клиентом» — только через завершённый Order (`Case.confirmedOrderId @unique`),
  ручной выдачи нет. Кейс без Order легален, но без бейджа, вне подтверждённых агрегатов,
  срок — с пометкой «по данным риелтора», ранжирование без бонуса +0.1.
- `DealType {SALE, RENT_OUT, BUY_ASSIST, RENT_ASSIST}`; `BriefObjectType → PropertyType` (+ NEW_BUILD).
- Видимость цены сделки: EXACT/RANGE/HIDDEN, дефолт RANGE; точная цена при RANGE/HIDDEN
  не отдаётся ни одной процедурой, включая OG.
- `daysOnMarket` — только SALE/RENT_OUT; агрегаты — по дериватам дат Order; пороги показа:
  медиана профиля ≥ 5 подтверждённых, агрегат района ≥ 10.
- Вилка цен профиля для риелтора скрыта в MVP; поля комиссии не существует.
- Каталог `/realtors` + SEO-страницы районов — в MVP; подборки районов и витрина агентства — Фаза 1.5.
- Челленджи — из MVP; посты — первые под нож.
- Seed: перевес риелторов (~24/16 специалистов, ~80 сделок / ~40 интерьерных кейсов).
- Канонический маршрут кейса подтверждён: **/case/{slug}** (в docs/10–13 встречается /c/{slug} —
  считать приведённым к канону).

## §14. Принцип простоты (Dars, 07.2026)
- Делаем только полезные и необходимые функции. Профессионально, но НЕ сложно.
- Ядро ценности: рассмотреть специалиста, его кейсы и работу — вся базовая информация
  в 1–2 клика. Каталог специалистов — главный канал дискавери наряду с лентой.
- Мастер кейса — максимум 3 шага; формы — минимум полей, умные дефолты.
- Не копаем до дна: фичи за пределами ядра откладываются, а не усложняются.

## §15. M2-backend (07.2026)
- Dev-БД без Docker-демона (песочницы/CI): системный PostgreSQL 16 через scripts/dev-db.mjs
  (порт 5433, trust, только localhost). Обычная разработка — docker-compose.dev.yml.
- Auth: OTP-коды и сессии хранятся ТОЛЬКО как SHA-256-хэши; cookie httpOnly+lax+secure(prod);
  попытка ввода кода списывается атомарно ДО сравнения (гонки не обходят лимит 5);
  сравнение — timingSafeEqual. `OTP_DEV_MODE=1` возвращает код на экран только номерам
  +9967000XXXXX (тестовый диапазон сида) — не обходит auth реальных номеров.
- Изображения кейсов принимаются только из своего пайплайна (/uploads/*.webp);
  вилка цены — derivePriceRange в packages/core (не вырождается на малых суммах).
- Отзыв на странице кейса — только если его заказ совпадает с кейсом (до Case↔Order в M4);
  «история» кейса — только авторское описание из БД, без шаблонных текстов.
- Черновик мастера честно живёт в localStorage; фото — сразу на сервере.
- i18n (ru/ky/en) и онбординг-мастер из M2 перенесены в следующий блок (§14: не всё сразу).

## §16. M4 — петля доверия (07.2026)
- Воронка MVP: прямые заявки (`leads.create`) → тред → заказ → отзыв → бейдж. Брифы и отклики —
  вторая воронка, отложены (M4.5): сначала проверяем прямой контакт, он проще (§14).
- Тред переиспользуется на пару клиент↔специалист; повторная заявка добавляется сообщением
  с префиксом «По кейсу «…»:». Один АКТИВНЫЙ заказ на тред — частичный уникальный индекс
  `order_one_active_per_thread` (state NOT IN COMPLETED/CANCELLED).
- Взаимность условий: заказ предлагает только специалист, переход discussion→agreed делает
  ТОЛЬКО клиент (API-guard поверх canTransitionOrder: actor='client', иначе 403
  «Условия подтверждает клиент»). Специалист не может «договориться сам с собой».
- Бейдж «Сделка подтверждена клиентом»: `Case.confirmedOrderId @unique` — один завершённый
  заказ подтверждает ровно ОДИН кейс. Привязка атомарна (updateMany where dealConfirmedAt IS NULL);
  гонки и повторы гасятся P2002 с человеческим сообщением. Агрегаты (confirmedDealsCount,
  медиана срока ≥5 подтверждённых) пересчитываются честно после каждой привязки/отзыва.
- delivered ставит autoConfirmAt = +7 дней (AUTO_CONFIRM_DAYS в core), UI показывает срок обеим
  ролям; сам автопереход выполнит воркер (apps/services, BullMQ) — отложен, поле уже живёт.
- Чат — поллинг (4с сообщения / 8с заказ, общий кеш): WS появится в apps/services вместе с ботом.
  Споры (disputed) и чек-поинты заказа — схема готова, UI вне MVP-петли.
- Смоук M4: 21 проверка (вход двух ролей, заявка, изоляция треда 404, права на предложение 403,
  фейковый переход 403, честный путь до completed, отзыв не-клиентом 400, дубль отзыва 400,
  привязка+бейдж на странице, витрина, повторная привязка 400, self-agreed 403,
  «один заказ = один бейдж» 400).

## §17. M4.5 — авто-подтверждение и брифы (07.2026)
- Авто-подтверждение стало честным: runAutoConfirm() переводит DELIVERED с истёкшим
  autoConfirmAt в COMPLETED актором system (инвариант из core: delivered→completed by client|system).
  Оптимистический updateMany (клиент мог успеть сам), autoConfirmed=true, OrderEvent
  byUserId=null + reason='auto_confirm' — след для арбитража. Агрегаты пересчитываются.
- Крон — /api/cron/auto-confirm (GET/POST), Bearer CRON_SECRET, fail-closed: без секрета 401.
  Часа достаточно (точность дедлайна — дни). BullMQ/apps/services не заводим до бота (M6).
- Брифы (вторая воронка): клиент публикует задачу (объект, район, бюджет-вилка опционально),
  специалисты откликаются — сообщение + до 3 СВОИХ опубликованных кейсов + оценка. Лимит
  Free 10/мес — canRespondToBrief из core, счёт по createdAt текущего календарного месяца.
  Один отклик на бриф: unique(briefId, specialistId), гонка → P2002 → человеческое 400.
- Доступ: бриф видят владелец и любые специалисты; клиент-посторонний — 404 (getBriefView
  → null). Владелец открывает чат по отклику (accept): тред пары переиспользуется (M4),
  первое сообщение «По брифу «…»» — идемпотентно (updateMany-гейт по статусу: параллельный
  accept не дублирует сообщение).
- Автоскрытие контактов (решение 03/7) реализовано минимально: hideContacts в packages/core
  (телефоны +996/локальные 0XXX, @ники) применяется на ЧТЕНИИ к текстам брифов и откликов;
  оригинал в БД не меняется. Цены/даты/площади не задеваются (тесты в core). Кейсы/чат —
  вне scope: в чате контакты разрешены by design.
- «Просмотрен» честно: открытие откликов владельцем ставит viewedAt + SENT→VIEWED.
- Статусы SHORTLISTED/DECLINED/HIDDEN — в схеме, UI отложен (§14: не всё сразу).
  Лимиты (Free 10 откликов/мес, 10 открытых брифов) — best-effort: гонка параллельных
  запросов может дать +1 сверх, это осознанно (мягкий продуктовый стоп, не БД-инвариант).
- Окно квоты — календарный месяц по Бишкеку (UTC+6): quotaMonthStart в core, один и тот же
  helper в мутации respond и в показе остатка.
- /briefs специалисту показывает и его СОБСТВЕННЫЕ брифы отдельной секцией (риелтор
  продаёт своё) — из ленты открытых свои исключены.
- Авто-подтверждение: переход и OrderEvent — одна транзакция (append-only журнал);
  секрет крона сравнивается timing-safe. Смоуки закоммичены: scripts/smoke-m4.mjs (21),
  scripts/smoke-m45.mjs (24), очистка — scripts/smoke-cleanup.sql.
- /briefs ролевая: специалист — лента открытых задач, клиент — «мои брифы». Одна страница,
  меньше маршрутов.
- Смоук M4.5: 24 проверки (крон 401/до дедлайна/просрочка/идемпотентность/отзыв после
  авто-завершения; брифы: гость 401, свой бриф 400, без профиля 403, чужой кейс 400,
  дубль 400, VIEWED, посторонний 404, чужой accept 404, контекст в чате, accept
  идемпотентен, закрытие, отклик в закрытый 400).

## §18. M5 — модерация (07.2026)
- Скоуп M5-лайт (§14): премодерация новичков + жалобы + очередь модератора + страйки.
  Соц-слой (M5.1), верификация (M5.2), pHash/арбитраж споров — следующей волной.
- Trust-tiers (решение 03/4) включены: NEW → первые кейсы в PENDING_REVIEW (+ModerationItem
  NEW_USER_PREMOD), в ленте/витрине/по прямой ссылке чужим не видны; автор видит свой кейс
  с баннером статуса (на проверке / отклонён с причиной / скрыт). 3 одобрения → TRUSTED,
  дальше публикация мгновенная. Инварианты — packages/core/moderation.ts.
- Жалобы: кнопка на странице кейса, доступна гостям. Идентичность гостя — HMAC(IP)
  (реализация решения backend №14: cookie подделывается ротацией, IP — нет; соседи по NAT
  делят лимит — осознанный компромисс MVP). Дедуп «то же лицо + тот же кейс» →
  duplicate:true; лимит 10/сутки → 429; сверх 5 анонимных жалоб на один кейс в сутки —
  принимаем молча, очередь не растёт. Скрытый кейс повторно не репортится.
  Причины — enum схемы, лейблы в data.ts. Жалобы на отзывы — схема готова, UI позже.
- /admin (MODERATOR/ADMIN, остальным «не существует» — 404 и в UI, и в API): очередь
  премодерации (одобрить / отклонить с причиной для автора) + жалобы (скрыть контент /
  «жалоба не подтвердилась»). Все действия — транзакции с updateMany-гейтом (двойной клик
  и гонки → 409) и записью в AuditLog (append-only).
- Скрытие по жалобе = страйк автору контента; 3 страйка → frozenAt (core.shouldFreeze).
  Замороженный не создаёт контент (кейсы/заявки/брифы/отклики — 403 человеческим языком),
  чтение и чат по действующим заказам остаются. Для отзыва страйк — автору отзыва,
  пересчёт витрины — специалисту из отзыва.
- Дыра M2 закрыта: скрытый (hiddenAt) кейс раньше открывался по прямой ссылке —
  теперь публично невидим; автору И модератору показывается с баннером статуса
  (премодерация «вслепую» по обложке из очереди не работает — модератор открывает кейс).
- Один инцидент = один страйк: повторный hide по второй жалобе на уже скрытый контент
  резолвит жалобу без страйка. Скрытые кейсы не считаются в порог TRUSTED и в dealCasesCount.
  Новичок не заливает очередь: ≥5 PENDING_REVIEW → «дождитесь проверки». Отзывы замороженным
  тоже закрыты (публичный контент). orders.propose замороженным оставлен — вопрос к Dars.
- Смоук M5 — scripts/smoke-m5.mjs, 22 проверки; старые смоуки работают от TRUSTED-юзеров
  (премодерация проверяется отдельно). Сид: модератор +996700000099, новичок с кейсом
  в очереди, 2 живые жалобы.

## §19. M7 — SEO и аналитика (07.2026)
- Метаданные: metadataBase из NEXT_PUBLIC_SITE_URL; generateMetadata у кейса и профиля
  (title/description/canonical/OG); getCase/getSpecialist в React cache() — metadata и
  страница делят запрос.
- OG-карточки генерируются на лету (next/og): кейс и профиль 1200×630, сторис-визитка
  1080×1920 (?download=1 — файл). Кнопка «Поделиться» на кейсе: системный share /
  копирование / скачивание визитки — маркетинговый инструмент специалиста. Шрифты —
  Liberation TTF в репо (satori не умеет woff2 и глифы ★/✓ — текст вместо символов);
  фото в карточке — только jpeg/png (mock), webp из аплоадов → типографская карточка
  (конверсия для OG — вместе с R2-пайплайном). Инвариант цены сохранён: OG использует
  те же DTO (точная цена только при EXACT).
- JSON-LD: профиль — RealEstateAgent (риелторы, docs/05 §7) / Person + AggregateRating +
  3 Review; кейс — CreativeWork + BreadcrumbList (НЕ Product/Offer — мы не листинг);
  только на публичных страницах.
- sitemap.xml (кейсы published+не скрытые, профили) + robots.txt (закрыты /admin,
  /messages, /briefs, /saved, /api, /login, /contact).
- Аналитика — transactional outbox (AnalyticsOutbox из M1-схемы): track(tx) внутри
  доменных транзакций (lead_created, brief_accepted, case_published viaModeration,
  auto-подтверждение), trackSafe вне (никогда не роняет основной поток). События:
  session_login, case_pending/published, lead_created, order_proposed/agreed/completed/
  cancelled (auto-флаг), review_created, brief_*, report_created. PostHog — воркером
  после получения ключей; события копятся с первого дня.
- Дашборд владельца /admin/stats (MODERATOR/ADMIN): воронка 30д и контент — из доменных
  таблиц (честно с первого дня), активность (7/30д) — distinct actorId из outbox;
  топ районов по подтверждённым сделкам. Одна серия — один цвет, подписи текстом (dataviz).
- Сид: 35 демо-событий за 30 дней — дашборд живой из коробки.
- Смоук M7 — scripts/smoke-m7.mjs (17 проверок: sitemap/robots/OG/JSON-LD/canonical/
  события/гарды дашборда).
