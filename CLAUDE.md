# ATELIER

Визуальная платформа репутации специалистов недвижимости (КР → КЗ/УЗ).
**Realtor-first**: риелторы — первая вертикаль (docs/05-realtors-first.md), остальные — вторая волна.
Формула: портфолио → репутация → клиенты → рост. Приоритет №1 — UX/UI.

## Статус
M1+R1+M2/M3+M4+**M4.5** завершены. Обе воронки живые поверх Postgres. Прямая: заявка → тред
(чат на поллинге, тред переиспользуется на пару) → заказ (предлагает специалист, условия
подтверждает ТОЛЬКО клиент) → сдан → принят → отзыв → привязка кейса = бейдж «Сделка
подтверждена клиентом». Обратная (M4.5): бриф клиента → отклики специалистов (сообщение +
до 3 своих кейсов + оценка; Free 10/мес из core) → клиент открывает чат (тот же тред пары).
Авто-подтверждение честное: /api/cron/auto-confirm (Bearer CRON_SECRET, fail-closed) завершает
просроченные DELIVERED актором system (autoConfirmed, OrderEvent reason='auto_confirm').
Инварианты в БД: один заказ = один бейдж (Case.confirmedOrderId @unique), один активный заказ
на тред (частичный индекс), один отклик на бриф (unique пары). Смоуки: M4 21/21, M4.5 24/24.
Тесты core 22/22. Dev-БД: `pnpm db:start` (PG16 без Docker); `OTP_DEV_MODE=1` — код на экран
ТОЛЬКО тестовым +9967000XXXXX.
Дальше: i18n ru/ky/en + онбординг / M5 модерация / M6 Telegram-бот+уведомления.

## Жёсткие принципы
- Никаких кредитных/процентных механик; поля комиссии не существует.
- Отзывы только по завершённым заказам; переходы заказа — canTransitionOrder (packages/core).
- Точная цена сделки при RANGE/HIDDEN не отдаётся никогда; телефоны скрыты до заявки.
- Конфликт «удобство vs скорость» — в пользу удобства. Инварианты — только в packages/core.
- Каждый блок: план → реализация → design-review (циклы) + code-review → доказательства → коммит →
  показ Dars. Детали: .claude/skills/atelier-conventions.
